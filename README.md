# 🌐 DCinside 웹 크롤러 & 데이터 분석기

*   Python 기반의 웹 크롤링 프로젝트로, 커뮤니티 사이트 '디시인사이드'의 게시글 및 댓글 데이터를 수집, 처리, 분석하는 기능을 구현하였습니다.

### 1. 프로젝트 소개
*   **목표**: 특정 주제에 대한 여론이나 트렌드를 파악하기 위해, '디시인사이드'라는 대형 온라인 커뮤니티의 데이터를 자동으로 수집하고 분석하는 프로그램을 개발하였습니다.
*   **의의**: 이 프로젝트를 통해 **대용량 데이터 수집 및 처리 능력**과 **업무 자동화 역량**을 보여드리고자 하였습니다.

### 2. 주요 기능
*   **게시글/댓글 자동 수집**: 지정된 게시판(예: 국내야구 갤러리)의 수많은 게시글 목록과 각 게시글에 달린 댓글들을 자동으로 가져옵니다.
*   **데이터 정제 및 저장**: 수집한 데이터를 `pandas` 라이브러리를 사용해 표(CSV 파일) 형태로 깔끔하게 정리하고 저장합니다.
*   **토픽 시각화**: 수집된 게시글들의 제목을 분석하여, 가장 많이 언급된 단어들을 시각적으로 보여주는 '워드 클라우드'를 생성합니다. 이를 통해 해당 게시판의 주요 관심사를 한눈에 파악할 수 있습니다.

### 3. 프로젝트를 통해 얻은 역량
*   **문제 해결 능력**: 웹사이트는 데이터를 쉽게 가져가지 못하도록 복잡하게 구성된 경우가 많습니다. 특히 댓글처럼 동적으로 로딩되는 데이터를 수집하기 위해 `Selenium`이라는 기술을 도입하여 문제를 해결하였습니다.
*   **성능 개선 경험**: 수십만 페이지에 달하는 데이터를 빠르게 수집하기 위해, '병렬 처리(`multiprocessing`)' 기술을 적용하여 크롤링 속도를 크게 향상시켰습니다.
*   **데이터 활용 능력**: 단순히 데이터를 수집하는 것을 넘어, `konlpy` (한국어 자연어 처리) 라이브러리를 활용해 텍스트 데이터를 분석하고, `WordCloud`로 시각화하는 경험을 통해 데이터의 가치를 창출하는 능력을 길렀습니다.

### 1. 프로젝트 개요
본 프로젝트는 Python을 사용하여 디시인사이드의 데이터를 수집하고 분석하는 엔드투엔드(End-to-end) 파이프라인을 구축한 것입니다. 정적 콘텐츠에는 `BeautifulSoup`을, 동적으로 로드되는 댓글 데이터에는 `Selenium`을 사용하는 하이브리드 방식을 채택하여 수집 효율성과 정확성을 모두 확보하였습니다. 또한, 대규모 크롤링 작업의 성능 병목 현상을 해결하기 위해 `multiprocessing`을 이용한 병렬 처리를 구현하였습니다.

### 2. 사용 기술
*   **Language**: `Python`
*   **Core Libraries**: `requests`, `BeautifulSoup4`, `selenium`, `pandas`, `multiprocessing`
*   **Data Analysis & Visualization**: `konlpy`, `wordcloud`, `matplotlib`
*   **Data Format**: `CSV`

### 3. 시스템 아키텍처 및 처리 흐름
핵심 로직은 `DCinsideRead` 패키지 내에 모듈화되어 있으며, 처리 과정은 다음과 같습니다.

1.  **게시글 목록 수집 (Static Crawling)**
    *   `get_page_and_base_url_dictionary`: 사용자가 지정한 갤러리(예: "국내야구", "클래식")의 URL 및 페이지 정보를 가져옵니다.
    *   `read_lists_of_posts_and_save_it_to_csv`: `requests`와 `BeautifulSoup`을 사용하여 게시판 각 페이지의 HTML을 파싱하고, 게시물 번호, 제목, 작성자, 날짜, 조회수 등의 메타데이터를 추출합니다.
    *   **병렬 처리**: 수집할 페이지가 많을 경우, `multiprocessing.Pool`을 생성하여 여러 페이지를 동시에 크롤링함으로써 전체 작업 시간을 획기적으로 단축시킵니다.

2.  **댓글 수집 (Dynamic Crawling)**
    *   디시인사이드의 댓글은 JavaScript를 통해 비동기적으로 로드되므로, `Selenium WebDriver`를 사용하여 브라우저를 직접 제어합니다.
    *   `get_reply_all_html`: `Selenium`으로 특정 게시물에 접속한 뒤, 댓글 페이지네이션(pagination) 버튼(e.g., '2', '3', '다음')을 프로그래밍 방식으로 모두 클릭하여 숨겨진 모든 댓글이 렌더링되도록 합니다.
    *   모든 댓글이 로드된 페이지의 소스(`page_source`)를 `BeautifulSoup`으로 파싱하여 댓글 작성자, 내용, IP, 날짜 등의 상세 정보를 추출하고 `pandas.DataFrame`으로 구조화합니다.

3.  **데이터 저장 및 관리**
    *   수집된 게시글 및 댓글 데이터는 `pandas` DataFrame으로 변환됩니다.
    *   `to_csv()` 메소드를 사용하여 데이터를 체계적인 CSV 파일로 저장하며, 파일명에는 갤러리 ID와 수집 시각을 포함하여 관리를 용이하게 합니다.

4.  **데이터 분석 및 시각화 (Application Example)**
    *   `make_word_cloud.py` 스크립트는 수집된 데이터의 활용 예시를 보여줍니다.
    *   CSV 파일에서 게시글 제목(`title`)들을 불러와 하나의 문자열로 합칩니다.
    *   `konlpy.tag.Okt` 형태소 분석기를 사용하여 한국어 문장에서 명사(Nouns)만 추출합니다.
    *   `collections.Counter`로 명사의 빈도를 계산하고, `WordCloud` 라이브러리를 통해 빈도가 높은 단어들을 시각화하여 저장합니다.

### 4. 코드 리뷰 및 고찰

#### 🟢 잘된 점 (Strengths)

1.  **하이브리드 크롤링 전략**
    `requests/BeautifulSoup`의 빠른 속도와 `Selenium`의 동적 콘텐츠 처리 능력을 결합하여, 각기 다른 웹 환경에 맞는 최적의 도구를 선택하고 적용하였습니다.

2.  **성능 최적화를 위한 병렬 처리 구현**
    대용량 데이터 수집 시 발생할 수 있는 성능 저하를 미리 예측하고, `multiprocessing`을 도입하여 CPU 자원을 효율적으로 활용하였습니다.

3.  **모듈화 및 재사용성**
    크롤링 로직을 `DCinsideRead`라는 설치 가능한 패키지 형태로 구성하고, `setup.py`를 작성하는 등 코드의 재사용성과 유지보수성을 고려하여 설계하였습니다. `참고 사이트 문서 목록...` 파일에서 PyPI 배포를 목표로 한 점은 SW 공학적 모범 사례를 따르려는 노력을 보여줍니다.

#### 🟡 프로젝트 회고 및 개선 방향 (Retrospective & Future Improvements)

1.  **예외 처리 및 로깅 강화**
    현재 테스트 코드들에는 네트워크 오류, 웹사이트 구조 변경 등으로 인해 발생할 수 있는 예외(Exception)에 대한 처리가 부족합니다. `try-except` 구문을 적극적으로 활용하고, `print` 대신 Python의 `logging` 모듈을 도입하여 에러 발생 시 원인을 추적하고 복구할 수 있는 견고한(Robust) 크롤러로 개선할 수 있습니다.

2.  **설정 관리의 유연성 확보**
    "국내야구", "클래식"과 같은 갤러리 이름이나 크롤링 페이지 수 등의 변수들이 코드 내에 하드코딩되어 있습니다. 이러한 설정 값들을 별도의 `config.ini` 또는 `JSON` 파일로 분리하면 코드를 직접 수정하지 않고도 다양한 대상을 크롤링할 수 있어 프로그램의 유연성과 확장성이 높아집니다.

3.  **코드 리팩토링 및 테스트 자동화**
    다수의 `test*.py` 파일에 존재하는 주석 처리된 코드들과 중복 로직들을 정리하고, 재사용 가능한 함수로 리팩토링할 필요가 있습니다. 또한, `pytest`와 같은 프레임워크를 도입하여 핵심 기능에 대한 단위 테스트를 작성하면 향후 기능 변경 및 유지보수 시 코드의 안정성을 보장할 수 있습니다.

4.  **의존성 관리 표준화**
    `requirements.txt` 파일이 Git LFS 포인터로 되어 있어, 프로젝트에 필요한 라이브러리 목록을 명시적으로 관리하고 있지 않습니다. `pip freeze > requirements.txt` 명령을 통해 의존성 목록을 생성하거나, `pipenv`나 `Poetry` 같은 현대적인 패키지 관리 도구를 사용하는 것을 고려해볼 수 있습니다.
